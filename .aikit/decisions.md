# Decisions

Why this project is built the way it is, oldest first. One entry per decision that changes a
contract, a dependency, a data format or the architecture; IDs are consecutive and never reused.

### ADR-001: Stdlib-only SQLite FTS5 memory, no FAISS
- **Date**: 2026-11-07
- **Status**: Accepted
- **Context**: Stage 2 verified neurocore FAISS dep heavy; cheaper alternative required instrument parity.
- **Decision**: Brain v1 uses SQLite WAL+FTS5 only; FAISS adoption gated on recall@k delta >=5%.
- **Consequences**: Zero third-party deps; vector recall deferred.

- **Decision**: Telemetry schema 2 JSONL with fsync-before-exec; ablation ops hub_zero/lesion/shuffle in telemetry/ablate.py; recompute in evals/recompute.py never reads self-report scalars.
- **Consequences**: Ablation runs before any claim; verdict stays UNKNOWN until Stage 4.

- **Date**: 2026-11-07

### ADR-004: Planner reads memory and hub for loop avoidance (negative result)
- **Date**: 2026-11-07

- **Decision**: Planner.plan reads hub via read_hub and recent positions from memories; stuck repeats switch to y-first step. Deterministic, rule-based, no new deps.
- **Consequences**: Gate stays 38 OK; T1 pooled phi 0.0226 vs null 0.0106, syn 0.0265 vs null 0.0773 — E1' still FAIL; verdict stays UNKNOWN. No threshold moved.

### ADR-006: Persistent outcome accounting with explicit substrate error counters
- **Date**: 2026-11-07
- **Status**: Accepted
- **Context**: Agent.run recorded persistent SelfModel ok=True on every step, so S[0] (errors) was constant zero with zero variance; six `except Exception: pass` blocks hid substrate failures and failed the hygiene gate (4/5).
- **Decision**: Record persistent ok True only when step reward is positive (reward > 0.0); unrewarded steps record ok False, so error_rate is the fraction of unrewarded steps. Each persistent-update failure path increments substrate_errors() by module key instead of bare pass; the loop still never raises from these paths. Test-cleanup swallows carry scoped `hygiene: allow [silent-except]` markers.
- **Consequences**: 43 tests OK; aikit check 5/5; S carries reward-timing variance; phi remains at floor and syn is independent of S (lesion_s delta 0.0), so no emergence claim — verdict stays UNKNOWN.

### ADR-007: Dead-end-entry lookahead with least-visited tie-break in planner
- **Date**: 2026-11-07
- **Status**: Accepted
- **Context**: T3 seed 15 took 15 steps vs 13 optimal: x-first ordering walked into column x=6 blocked at (6,1) and oscillated (5,0)<->(6,0) before the stuck backstop fired. T1 ordering audit showed nearest-greedy equals optimal on all 30 seeds (no headroom there — dead end).
- **Decision**: _step_toward prefers distance-reducing candidates that keep a free one-step exit toward the goal (goal cell trivially viable), then least-visited cells from planner memory, with stable x-first/fallback order breaking remaining ties. No new deps; deterministic.
- **Consequences**: 46 tests OK; aikit check 5/5; T3 seed 15 15->13, 30-seed totals T1 466 / T2 240 / T3 219->217 with all other seeds byte-identical; blind-memory ablation truncates seed 65 at 200 steps with zero reward (memory coupling proven); seed 65 residual detour 8 vs 6 remains as known 2-ply-trap boundary.

### ADR-008: Two-step exit lookahead in planner viability check
- **Date**: 2026-11-07
- **Status**: Accepted
- **Context**: Cycle 2 left T3 seed 65 (target [3,3], obstacle [3,2]) at 8 steps vs 6 optimal: 1-step lookahead entered (3,0)->(3,1), a cul-de-sac whose only exit is blocked. A 100-seed scan also showed the depth-1 rule plus visits was the only guard on trap seeds.
- **Decision**: _has_exit checks two steps ahead (candidate exit must itself have a free exit or be the goal; depth bounds recursion, branching <= 2). Least-visited tie-break retained: without it seed 74 cycles to the 200-step cap with zero reward.
- **Consequences**: 47 tests OK; aikit check 5/5; T3 seed 65 8->6 (optimal); zero detours across T3 seeds 0-99 (total 683 vs 874 memory-blind, a +191 gap); blind-memory ablation moved to seed 74 (intact 9 vs blind 200/zero-reward).

### ADR-009: Optimal-tour first pick for forage item ordering
- **Date**: 2026-11-07
- **Status**: Accepted
- **Context**: Cycle 2 audited only seeds 0-29 (greedy==optimal throughout) and closed ordering as a dead end. A cycle-4 100-seed audit found 3 greedy traps: seeds 71/74/78 took 18/14/20 steps vs 16/12/18 optimal (+2 each).
- **Decision**: Planner picks the first cell of the shortest Manhattan tour over remaining items (exhaustive permutations, deterministic: cells sorted, first strictly-shortest wins) instead of nearest-first. Removes the now-unused _nearest helper.
- **Consequences**: 49 tests OK; aikit check 5/5; T1 seeds 71/74/78 at optimal (16/12/18), 100-seed T1 total 1587->1581 with all other 97 seeds byte-identical; T2/T3 untouched.

### ADR-010: Remove the inert stuck-override backstop from the planner
- **Date**: 2026-11-07
- **Status**: Accepted
- **Context**: ADR-004 added a stuck detector (position repeated >=2 in recent memories forces one y-first step). After cycles 2-3, 2-ply lookahead plus least-visited ordering handles all traps; the override fired 238 times in 3064 plan calls without changing any outcome.
- **Decision**: Delete the stuck computation and the y-first override branch in _toward. positions and visit counts stay: visit ordering remains load-bearing (seed-74 ablation). T2 delayed-match wait rule stays: it is task-contract semantics, unreachable today (min target distance 7 > 2) but falsifiable by layout change.
- **Consequences**: 49 tests OK; aikit check 5/5; -6 lines; 100-seed totals per task byte-identical (T1 1581, T2 800, T3 683), all runs complete.

### ADR-011: Quarantine-and-reopen recovery for corrupt store files
- **Date**: 2026-11-07
- **Status**: Accepted
- **Context**: MemoryStore opened a corrupt file into DatabaseError at first execute and leaked the connection handle (Windows tempdir cleanup then failed with PermissionError). PRINCIPLE-013 requires corrupt -> quarantine for state files.
- **Decision**: Open validates via schema setup plus PRAGMA quick_check; on sqlite3.DatabaseError the failed connection is closed, the file (plus WAL sidecars) is moved to path + ".corrupt" (numbered on collision), and a fresh store opens. recovery_notes() exposes the log, empty on clean opens.
- **Consequences**: 54 tests OK; aikit check 5/5; corrupt fixture recovery 0/1 -> 1/1 with byte-identical quarantine preserved; no behavior change on healthy files.

### ADR-012: Swappable small-model backend seam (llama.cpp first)
- **Date**: 2026-11-07

### ADR-014: Goal-complete model-seam observations and prompts
- **Date**: 2026-11-07
- **Status**: Accepted
- **Context**: Planner.plan built backend obs with only task/x/y/steps/legal and build_prompt rendered only those, so distinct goal states collided to identical obs/prompt and any obs-limited backend had zero steering signal.
- **Decision**: Planner includes target, items_positions, obstacles, and cue copies in obs when present in state; build_prompt appends deterministic Target/Items/Obstacles/Cue lines when those keys are present, leaving minimal-obs prompts byte-identical. No new deps; backend None rule path unchanged.
- **Consequences**: 63 tests OK; aikit check 5/5; rule totals byte-identical (T1 466 / T2 240 / T3 217, trap seeds 16/8/13/6/9); fixed-rig syn 0.1246 phi 0.0 and hub0/m0 kill with p0/s0 no-op unchanged; obs-oracle on 4 steerable seeds 200/0.0 truncated -> 16/8/13/6 optimal with variance 0; minimal-obs ablation restores truncation.

### ADR-015: Visit-complete model-seam observations and prompts

### ADR-016: Episode-memory goal recall for transient state dropout
- **Date**: 2026-11-07
- **Status**: Accepted
- **Context**: Planner read goal keys only from the current state, so transient dropout (target/items stripped at plan-time with memories intact) truncated runs the episode buffer could have saved.
- **Decision**: Planner recalls missing target/items_positions/obstacles/cue from provided episode memories (most-recent-first, deterministic copies) for both rule geometry and backend obs; present keys (including empty lists) never trigger recall. No new deps; no world change.

Boundary: persistent hidden worlds (saved states also hide) need full-history recall plus a new task family — reserved.

### ADR-020: Blocked-corridor entry deprioritization (distance-independent)
- **Date**: 2026-11-07
- **Status**: Accepted
- **Context**: Depth-only lookahead needs unbounded depth to see distant column/row blocks (seed 479: target [3,7] behind obstacle [3,6] at distance 6-7); a 400-499 scan found exactly this 1 trap (+2).
- **Decision**: In _step_toward grouping, sort each of viable/dead by (enters_blocked, visits) with stable order: entering the goal's column/row while an obstacle lies strictly between the candidate cell and the goal sorts after staying out; visits still break ties; x-first survives ties; backup (no goal-directed free cell) unchanged. O(1), deterministic, no new deps.
- **Consequences**: 80 tests OK; aikit check 5/5; T3 479 12 -> 10 (optimal); T3 400-499 total 677 -> 675 with all other 99 byte-identical; 500/500 T3 seeds optimal across 0-499; all prior totals unchanged; fixed-rig syn 0.0541 phi 0.0 unchanged; corridor+depth suffices here (blind == intact); visit-memory coupling still carried by seed-74 blind truncation.

### ADR-049: Serialize telemetry hash-chain appends with an AIKit-style advisory lock
- **Date**: 2026-11-07

### ADR-086: Lock release must own the lock it removes
- **Date**: 2026-11-09
- **Status**: Accepted
- **Context**: The telemetry, claim-store and calibration-store locks wrote `pid:timestamp` and release unconditionally unlinked the lock path. Behavior, standing, fixed-rig, evidence batteries and `policy_digest` are unchanged. Boundary: release remains a read-then-unlink pair, so a steal in the tiny window between the read and unlink is still possible; the change removes the deterministic long-held-lock deletion, not every theoretical race. ### ADR-094: World-geometry fingerprint for persisted layouts
- **Date**: 2026-11-09
- **Status**: Accepted
- **Context**: Recovery keyed layouts by `(task_id, seed)` only, and first-write-wins kept the first complete row forever. Two distinct worlds that reuse the same task id and seed (custom worlds, forced test layouts) therefore collided: warming the second world silently stored nothing, and its cold run recalled the first world's target, looping to the 200-step cap with 0.0 reward (measured: warm B 6/1.0, stored layout still A's `[6,7]`, cold B 200/0.0).
- **Decision**: Give `GridWorld` a deterministic `layout_fingerprint()` (SHA-256 over size/task/target/obstacles/initial items/cue). `Agent` resolves it through `world_fingerprint(world)` and passes it to `get_layout`/`save_layout`. The layouts table gains a nullable `fingerprint` column (in-place `ALTER TABLE` for older stores); a known stored fingerprint that differs from a known incoming one replaces the row, and `get_layout(..., fingerprint=...)` treats a mismatched row as absent. Legacy rows with a NULL fingerprint keep their previous first-write-wins behavior, so existing stores recover unchanged. Add `tests/test_layout_fingerprint.py` (collision, fingerprint stability, blind-fingerprint ablation). No new dependencies; no policy or behavior change for built-in worlds.
- **Consequences**: 452 tests OK; aikit check 5/5. The warm A -> warm B -> cold B sequence now recovers B at 6 steps/1.0 with B's geometry stored; the ablation (`world_fingerprint -> None`) restores the baseline 200/0.0 collision, so the fingerprint is load-bearing. Built-in warm-cold recovery stays 16/8/13/6 with 3/1/1/1, cold-first still 200 then 16/8/13/6, `store_reads` 1 cold / 0 warm, standing 466/240/217, fixed-rig syn 0.05411532 phi 0.0, and `policy_digest` decbfce3... are unchanged. Boundary: the store keeps one layout row per `(task, seed)`, so alternating distinct worlds under the same key leaves only the most recent world's layout recoverable; the fingerprint distinguishes worlds, it does not allocate a row per world; NULL legacy rows cannot be distinguished until a complete run rewrites them.

### ADR-099: Report the synergy estimator's column scope with its estimate
- **Date**: 2026-11-09
- **Status**: Accepted
- **Context**: `evals.estimators.synergy` builds its joint code from `trace[0]` and `trace[1]` only, but `evals.recompute` feeds it the full 9-column M/P/S/hub block row and reports the result as `syn`. Measured: appending a third column leaves `syn` byte-identical (0.11181316771575098 either way), so columns >= 2 are never read. In every cold-start case column 0 is constant, so `syn` is structurally 0.0 while column 7 carries MI 0.271; the battery printed `syn 0.0` with no way to tell "no integration" from "integration outside the measured columns". The integration-differential modes inherit this: `lesion_p`/`lesion_s` "change nothing" only because those columns are never read, and `hub_zero_rows` drives `syn` to 0.0 because hub[2] *is* the target column (swapping hub x/y leaves `syn` identical). The number is therefore unfalsifiable at the read site. A joint code over all columns was rejected by measurement, not taste: 8 bins^8 at n=15 puts every row in its own cell and inflates MI; pairwise block interactions across M/P/S/hub beat the permutation null in 0 of 6 pairs at n=15 and 0 of 5 seeds at n in 6..14.
- **Decision**: Make the scope explicit and machine-checkable rather than silently wider. Add `SYNERGY_COLUMNS = (0, 1)` and `synergy_scope(trace, target)` returning `columns`, `ignored_columns`, `n_rows`, `n_columns`, `constant_columns`, `sufficient` and a `reason` (`empty-trace`, `shape-mismatch`, `constant-scope-column`). `recompute` gains a `syn_scope` field carrying that report next to `syn`. `synergy` itself is unchanged, so every pinned value stays byte-identical. Add `tests/test_synergy_scope.py` (7 tests, including value parity with and without trailing columns and a recompute-level scope assertion). No new dependencies; no behavior, policy or estimate change.
- **Consequences**: 471 tests OK; aikit check 5/5. Fixed-rig `syn` 0.054115320909768228 and `syn_n` 0.10814360275702875 are bit-identical to their pins; `syn_scope` reports `sufficient: true` with columns [0, 1] and ignored [2..7]. All four cold-start cases now report `sufficient: false`, `reason: constant-scope-column`, `constant_columns: [0]` instead of a bare 0.0. Behavior, standing 466/240/217, cold-first and `policy_digest` are unchanged. Boundary: this makes the limit visible and un-ignorable at the read site; it does not widen the estimator. `syn` remains a two-column statistic, so a `sufficient: true` 0.0 is still "no interaction between those two columns and the target", not "no integration anywhere"; a wider criterion needs a sample size the n<=30 traces do not supply, and `phi` remains the cross-column readout for those.

### ADR-100: Measure a lesion's detectability instead of assuming it
- **Date**: 2026-11-09
- **Status**: Accepted

### ADR-101: One-level recall copies instead of a per-step history deepcopy
- **Date**: 2026-11-09
- **Status**: Accepted
- **Context**: `Agent._run_loop` calls `self.memory.recall(limit=None)` once per step and passes the result to `Planner.plan`. `Memory.recall` used `copy.deepcopy`, so each step recursively copied the whole episode history. The planner reads only `list(memories)[-4:]` and every other consumer (`_step_vectors`, the `_recall` probe walk) iterates the list without mutating it, so the recursive copy bought nothing. Measured on realistic nested states dicts: n=60 0.047677 s versus 0.000571 s, n=200 0.163636 s versus 0.004498 s for 60 calls — 36x to 84x, and it is O(n) per step inside an O(n) loop.
- **Decision**: Return one-level copies (`[dict(item) for item in ...]`) from `Memory.recall` for both the `limit=None` and bounded paths. `Memory.save` still stores a deepcopy, so the stored history remains isolated from callers. A caller can rebind or add keys on a returned dict without touching the store, which is the property the loop relies on; nested values are shared by reference and are never mutated by the planner. Add `tests/test_recall_cost.py` (4 tests: store isolation, a cost comparison against `deepcopy` at n=60/200, the pinned action quadruple, and a check that the planner leaves the recall argument unchanged).
- **Consequences**: 483 tests OK; aikit check 5/5. Standing 89 steps / 11.0 reward, T1 0-99 1581, holdout 500-599 738 (min 1, max 14), cold-start 16/8/13/6 with 3/1/1/1 and `store_reads` 1 per case, and `policy_digest` decbfce3... are all unchanged. Ablation: reinstating `copy.deepcopy` makes the same read 120.4x slower (0.222778 s vs 0.001850 s for 60 calls at n=200), so the cost is the cut, not the measurement. Boundary: nested values in a returned state are shared with the store, so a future caller that mutates `state["items_positions"]` in place would corrupt history; the planner does not, and the contract is stated in the docstring rather than enforced by a copy.

### ADR-104: Replay a log's actions through the world its header names
- **Date**: 2026-11-09
- **Status**: Accepted
- **Context**: `telemetry.verify_chain` proves the recorded bytes were not edited after writing, and `episode_verify.verify_episode_header` proves the header's task/seed/budget/policy are internally consistent. Neither reads the action sequence, so the trajectory itself was unverified. Measured: taking a real `T3_navigate:15` log, replacing every `kind == "step"` action with `"wait"` and re-emitting the records through `Telemetry` (so the chain is recomputed honestly) produced `verify_chain ok: True`, `verify_episode_header ok: True`, while replaying those actions left the world at `(0, 0)` with no reward. A log could therefore claim a solved episode it never ran, and every shipped verifier accepted it.
- **Decision**: Add `episode_replay.py`. `logged_steps(records)` selects the step action records; `replay_actions(task, seed, actions, max_steps)` drives a fresh `GridWorld` and returns each step's state/reward/done; `verify_action_replay(log_path, records=None, max_steps=200)` reads the header, replays every logged action, and compares the replayed reward with the log's recorded reward per step, the replayed terminal `done` with the log's, and the replayed length with the logged length. Findings are named (`reward-mismatch:<n>`, `done-mismatch`, `replay-short:<n><<m>`, `unreplayable-action: <detail>`, `missing-header`, `missing-seed`, `invalid-task`). Add `tests/test_episode_replay.py` (6 tests, including the chain-valid forgery).
- **Consequences**: 503 tests OK; aikit check 5/5. The honest log verifies on all three checks (`chain`, `header`, `replay`); the forged log passes chain and header and fails replay with `reward-mismatch:12` and `done-mismatch`. Standing 89 steps / 11.0 reward and `policy_digest` decbfce3... are unchanged; no agent or telemetry write path changed. Ablation: without `episode_replay` the forgery is accepted; with it the same bytes report the first divergent step. Boundary: replay proves the actions are consistent with the named world and seed, not that a model produced them; a forger who also replays a different action sequence to a victory that the world accepts would still verify, so this raises the cost of a trajectory lie without making logs unforgeable. Reward is compared against the world's own value, not against a claimed score.

### ADR-105: Compose action replay into claim-ref verification

### ADR-106: Check a verdict's machine claim against the replay
- **Date**: 2026-11-09
- **Status**: Accepted

### ADR-107: Name circular confidence in the self-model's calibration readout
- **Date**: 2026-11-09
- **Status**: Accepted
- **Context**: `Agent` records a step into the persistent self-model with `conf = 1.0 if reward > 0 else 0.5` and `ok = reward > 0`, so the recorded probability is the outcome by construction. `SelfModel.calibration()` then scored those pairs and reported `brier` 0.203125 / `skill` -0.333333 (T1:71), 0.230769 / -2.25 (T3:15) and 0.222222 / -1.25 (T3:74) as ordinary calibration results. ### ADR-126: The LIKE fallback searches the query's terms, not the raw expression
- **Date**: 2026-11-09
- **Status**: Accepted
- **Context**: `MemoryStore.recall` tries FTS5 `MATCH` and falls back to `LIKE` when the query raises `OperationalError`. The fallback used the query verbatim as a LIKE pattern. Measured against real agent-written rows (13 rows, keys like `T3_navigate:15:3`, JSON content): `recall("T3_navigate")` returns 13 via the FTS path, but `recall("T3_navigate AND (")` returned **0** — the fallback searched for the literal string `T3_navigate AND (`. OR content LIKE ?` disjunction per term (parameterised, still `ORDER BY id ASC LIMIT ?`). An empty term list returns `[]` rather than matching everything. Add `tests/test_recall_fallback.py` (6 tests against agent-written rows: term extraction, malformed query finds its rows, well-formed query unchanged, no-term query returns nothing, limit/ordering preserved, and a genuine miss is still a miss).
- **Consequences**: 656 tests OK; aikit check 5/5. `recall("T3_navigate AND (")` now returns 13 instead of 0; `recall("((( ")` and `recall("zzzz AND (")` still return 0, so the fix restores matches without inventing them; limit 3 returns the first three keys in id order. Memory, store-recovery and store-schema suites (16 tests) pass unchanged; standing 89 steps / 11.0 reward and `policy_digest` decbfce3... are unchanged. Ablation: with the raw-expression fallback the malformed query returns 0; with the term fallback it returns 13, and the other three queries are identical in both readings. Boundary: this fixes term extraction, not query semantics — `OR` between terms means a multi-term query is a disjunction, not an AND, and punctuation inside a term is still split.

- **Date**: 2026-11-09
- **Status**: Accepted

### ADR-136: Correct ADR-135's mechanism — duplicates are insufficient for independence, not for exact arithmetic
- **Date**: 2026-11-09
- **Status**: Accepted (supersedes the mechanism paragraph of ADR-135; the decision stands)
- **Context**: ADR-135 claimed a duplicated scope pair makes the joint code "a bijection of one column", so `i1 == i2 == ij`, `syn == -MI` and `syn_n == -1.0`. That was inferred from a 4-value test column and generalised without checking the pinned fixture. Checking it found the opposite: on the pinned `T1_forage:7` trace (15 steps, `c0 == c1 == 1..15`, target `[0,0,0,1,...]`), `i1 = 0.22314355131420976` but `ij = 0.5004024235381878` — so `syn = +0.05411532090976823`, **positive**. The cause is that `tj = c0 * 8 + bins(c1)` is injective (15 distinct codes) but `mutual_info_discrete(tj, ..., bins=64)` re-bins a range of 8..127, merging codes the joint had kept apart. A 4-value column stays inside the 64 bins and does give exactly `-MI`, which is why the first probe agreed.
- **Decision**: Keep the duplicate check and its verdict, and rewrite the reasoning and every docstring that carried the false claim: a duplicated pair has no *independent second signal*, so it cannot support an interaction claim regardless of which arithmetic regime applies. Add `tests/test_synergy_duplicate_mechanism.py` (5 tests) pinning the injectivity, the coarse-binning inflation (`ij` 0.5004024235381878 vs `i1` 0.22314355131420976), the positive artifact `+0.05411532090976823`, the exact `-MI` regime on a small-range column, and that both regimes exist so the claim must be about independence. Rename the ADR-135 test that asserted "cannot produce a positive gap" to `test_a_small_range_duplicate_gives_the_exact_minus_mi_result`, and mark the ADR-135 mechanism paragraph as corrected.
- **Consequences**: 718 tests OK; aikit check 5/5. The battery verdicts are unchanged from ADR-135 (17/17 insufficient, `coldstart` 4/4 constants, four batteries 13/13 duplicates), and the pinned `syn` +0.05411532090976823 is now correctly labelled an artifact of coarse joint binning rather than evidence of integration. Estimator, integration-differential and mechanism suites 16 tests OK; standing 89 steps / 11.0 reward and `policy_digest` decbfce3... are unchanged. Ablation: the ad-hoc 4-value fixture reproduces `syn == -MI` and would have kept the wrong claim alive; the pinned-fixture test fails under it, which is why the correct claim is stated as independence rather than arithmetic. Boundary: this corrects the *explanation*; it does not change `syn`'s values and does not fix the binning — a `bins` choice that inflated the joint is a separate estimator question with its own re-baseline.

### ADR-137: One bin count cannot serve both the joint and the marginals
- **Date**: 2026-11-09
- **Status**: Accepted (records the defect; the scaling is left as-is deliberately)
- **Context**: ADR-136 traced the positive-gap artifact to joint binning. Following it found the scale mismatch: `synergy` computes `ij = mutual_info_discrete(tj, target, bins=64)` while `i1`/`i2` use the default `bins=8`. Because `tj = c0 * 8 + bins(c1)`, the joint spans eight times the range of `c0`, so a single bin count cannot be right for both. - **Decision**: Record the defect and pin its measured shape rather than change the estimator. Add `tests/test_joint_binning_scale.py` (5 tests): the joint range is 8x the column range, `bins=8` and `bins=64` disagree on `ij`, the pinned gap changes sign between them for T1:71, the shipped value is the fine one (`syn = 0.0372826`), and `SYNERGY_COLUMNS` is the pair the joint uses. No production change.
- **Consequences**: 723 tests OK; aikit check 5/5. The `bins=8`/`bins=64` disagreement is now a pinned fact with exact values instead of a surprise, and the sign flip on T1:71 is recorded. Standing 89 steps / 11.0 reward and `policy_digest` decbfce3... are unchanged; no estimate moves. Ablation: reverting the joint to the default `bins=8` changes `T1_forage:71` from `+0.037283` to `-0.222647` and `T3_navigate:15` from `-0.057913` to `-0.164551`, which the sign-flip test catches. - **Date**: 2026-11-09
- **Status**: Accepted
- **Context**: Checking why each vector value appeared exactly twice found the cause: every step writes both an `action` record and a paired `result` record, and **both carry the same 9-column vector** (`[1,1,0,0,0,1,1,0,0]` for both on `T3_navigate:15` step 1). A 13-step episode therefore yields 26 vector rows, and every estimator saw each observation twice. The collinearity itself is real — de-duplicating leaves the dependent-pair count unchanged at 22 (defaults) / 31 (wired) — but every reported `n`, every contingency-table count, and every permutation-null tail was computed at `n = 2T`.
- **Decision**: Add `evals/recompute.dedupe_rows(rows)` collapsing *adjacent* identical rows (two different steps may legitimately share a vector, so non-adjacent repeats are kept) and apply it to `vec_rows` in `recompute` before the `phi`/`syn` paths. Add `tests/test_duplicate_rows.py` (8 tests) and `tests/test_corrected_counts.py` (5 tests) pinning the corrected counts.
- **Consequences**: 790 tests OK; aikit check 5/5. The correction is substantive, not cosmetic: cycle 144 reported **2 of 6** pinned traces and **3 of 17** battery slots as distinguishable from their permutation null; at the correct `n` the counts are **0 of 6** and **0 of 17** — every one of those "significant" verdicts was an artifact of doubled `n`. On `T3_navigate:65` the null has *zero spread* at `n=6` (every shuffle of the target gives `−0.450561…`), so nothing can be distinguishable, whereas at `n=12` it spanned `−0.4506…−0.2195` and the gap looked significant at `p_lower 0.015`. `syn` itself is unchanged (`−0.05791331748493783` on T3:15) because uniform duplication scales every count equally; `syn_scope.n_rows` now reports 13 instead of 26. `test_synergy_null_wiring.test_the_real_run_reaches_the_slot_with_a_verdict` was re-baselined from `distinguishable True` to `False`. Standing 89 steps / 11.0 reward and `policy_digest` decbfce3... are unchanged. Ablation: disabling `dedupe_rows` restores the spread and makes T3:65 "distinguishable" again while `n_rows` reports 26, failing 3 of the 5 corrected tests — so the corrected counts come from de-duplication, not from a change to the null. Boundary: this fixes the sample size, not the substrate — the vectors remain collinear and anti-synchronous (ADR-143), and the honest headline is now stronger than before: **no shipped trace and no battery slot carries a synergy distinguishable from chance**.

### ADR-145: The pair-level claims split into a correct estimate and a fabricated tail
- **Date**: 2026-11-09
- **Status**: Accepted
- **Context**: ADR-144 fixed `recompute` to de-duplicate rows, but the pair-level tests (`test_pair_scan`, `test_wiring_independence`) build their rows straight from `_vec_row` over the log, so they still measured at `n = 2T`. Re-running both conclusions at the correct `n` gave a split verdict. **Gate verdicts survive unchanged**: `(1,2)/(1,3)/(1,4)` are still refused as `constant-scope-column` at `syn +0.2599`, and `(0,6)` as `dependent-columns` at `syn +0.2062`. **Significance does not**: on `T3_navigate:15` fully wired, `p_upper` falls from 0.860/0.975/1.000/0.915/1.000 to 0.610/0.890/1.000/0.640/1.000 and every pair becomes `distinguishable False`; `anti_interactions` goes from 3 to 0. The reason the gaps are identical is exact: MI is a function of the joint probabilities and uniform duplication is a 2× copy, so `syn` is invariant — measured, `n=8` and `n=16` both give `−0.6931471805599453`. Only n-dependent quantities change.
- **Decision**: Point both pair tests at one observation per step (`dedupe_rows`), correct `test_wiring_independence`'s significance assertions (`test_the_strong_anti_correlations_are_distinguishable` → `test_no_anti_correlation_is_distinguishable_at_correct_n`; `test_anti_interactions_are_reported_separately` → `test_anti_interactions_are_empty_at_correct_n`), and add `tests/test_pair_conclusions.py` (7 tests) pinning both halves: the invariance of `syn` under uniform duplication, the survival of the gate verdicts, the unchanged gaps, and the collapse of significance.
- **Consequences**: 797 tests OK; aikit check 5/5. The record now separates what survived from what did not: the pair search's **structural** conclusions (which pairs are artifacts, which are independent) were correct all along, while its **tail probabilities** were not. Standing 89 steps / 11.0 reward and `policy_digest` decbfce3... are unchanged. Ablation: disabling `dedupe_rows` makes `(4,7)` distinguishable again and returns 3 anti-interactions, failing 2 of the 8 corrected tests. Boundary: this closes the correction chain opened in ADR-144 — after it, no remaining shipped claim rests on a `2T` sample; the substantive finding is unchanged and now unambiguous: five independent pairs exist, all are negative, and none is distinguishable from chance.

### ADR-146: Make the LLM seam pluggable and *checkable*
- **Date**: 2026-11-09
- **Status**: Accepted
- **Context**: `ModelBackend` was already an ABC with one method and `LlamaCppBackend` implemented it, but the seam was unusable for a new provider: `models/__init__.py` promises Ollama and in-process weights that do not exist; `evals/trust.py` keeps a local `BACKENDS` dict of test doubles at the wrong scope; `model_label()` derived the header pin from `model_path` and fell back to `type(backend).__name__`, so renaming a class silently invalidated every historical pin; and there was no way to validate a new provider except reading its code.
- **Decision**: Three additions, no change to any shipped behaviour. (1) `ModelBackend.identity()` becomes part of the protocol with an honest class-name default, so a provider that never declares one is detectable. (2) `models/registry.py` maps name → factory (`stub`, `llamacpp`, with the llama.cpp import kept lazy so the module has no subprocess or socket import); `build(name)` raises `KeyError` naming the available choices and `register` refuses duplicates, so an unknown name can never silently select a default. (3) `models/conformance.check_backend(provider, observation)` exercises a provider and reports `identity-from-class-name`, `non-string`, `no-proposal`, `illegal-token`, `non-deterministic` and `raises` — with `raises` reported but **not** treated as a violation, because raising is the contract for a fault and the caller is expected to count the fallback. `agent.model_label()` prefers a declared identity that is not class-name-derived, keeping the `model_path` fallback so existing headers keep matching.
- **Consequences**: 830 tests OK; aikit check 5/5. `check_backend` discriminates: conforming ok; alternating (`non-deterministic`); class-identity (`identity-from-class-name`); returns-none (`no-proposal`). `evals/backend_conformance.py` pins those four outcomes and both registered names, exiting 1 on drift. A mock provider is registered, built by name, driven through `Planner(backend=...)` and pinned via `model_label` **with no network and no model file**. `model_label(None)` is still `"rule"` and `model_label(StubBackend)` is still `"StubBackend"`, so no header pin moved; standing 89 steps / 11.0 reward and `policy_digest` decbfce3... are unchanged. Ablation: replacing `check_backend` with a rubber stamp fails 5 contract tests and 4 battery tests, so the seam is validated by the check rather than by the existence of a class. Boundary: conformance asserts *protocol* behaviour, not model fidelity — determinism is checkable only through a deterministic transport, because temperature and batching make byte-identical live output false; and `llamacpp` is registered but only identity-checked, since constructing it needs a server binary.

### ADR-147: A registry nobody can reach is not pluggable
- **Date**: 2026-11-09
- **Status**: Accepted
- **Context**: ADR-146 shipped `models.registry` with `register`/`build`/`names` and a conformance check, and the seam validated — but a survey of non-test callers found **zero** production uses of `build()`. The only importers were `models/conformance` (no) and `evals/backend_conformance.py`, so "choose a backend" still meant editing Python. Every battery in `evals/` instantiates its backend directly (~10 sites: `WaitingBackend()`, `PromptBackend(5)`, `DeclineBackend()`), and the repo had **no CLI for running the agent at all** — only `demo.py` (scripted world deltas), `inventory.py`, `run_verify.py` and `state_machines.py`. This is the fourth occurrence of the same defect class (ADR-121 `syn_scope`, ADR-131 `syn_sign`, ADR-139 `syn_null`): a facility built with no reachable caller.
- **Decision**: Add `run_agent.py` — `python -m run_agent --task X [--seed N] [--max-steps N] [--backend NAME] [--stub-script a,b,c]`. It builds the provider through `models.registry.build`, runs one episode, and reports `task`/`seed`/`backend` (what was asked for) separately from `model` (the label actually pinned). Exit 0 on a completed run, 2 on misuse: unknown task, unknown backend (message lists the registered names via `names()`), or `--backend stub` without `--stub-script`. A registered backend that fails at run time is **not** misuse — the planner counts the fallback — which is why the two labels are reported apart. Add `tests/test_run_agent_cli.py` (8 tests driving the module through a subprocess).
- **Consequences**: 838 tests OK; aikit check 5/5. `--task T3_navigate --seed 15` gives 13 steps / 1.0 / model `rule`; adding `--backend stub --stub-script right,right,right` gives the same 13 / 1.0 with model `StubBackend`, which is the historical label kept intact; `--backend nope` exits 2 printing `Available: llamacpp, stub`. `run_agent.py` is now the only production importer of `models.registry`, and naming a backend does not change a rule run. Standing 89 steps / 11.0 reward and `policy_digest` decbfce3... are unchanged. Ablation: removing `run_agent.py` makes all 8 tests error (module absent) and restoring it returns them to 0 — done at file level, because an in-process monkeypatch has **no effect** on tests that drive a subprocess, which I first tried and had to discard after it reported 0 failures. Boundary: this exposes the seam; it does not add a provider. `llamacpp` is selectable but needs a real `--model-path` and a server binary, so the only provider actually exercisable from the CLI today is `stub`. Adding a genuinely different provider is the next step, and it must pass `models.conformance` before it can be trusted.

### ADR-148: A scan of many pairs needs a family-wise null
- **Date**: 2026-11-11
- **Status**: Accepted
- **Context**: `evals.pair_scan.interactions` returned every pair outside its own 5% permutation tail. A scan tests every valid pair at once, so a 28-pair scan expects about 1.4 positives at `alpha=0.05` before any interaction exists. Measured on a synthetic trace with a planted XOR pair and six independent binary decoys (`n=24`, `seed=28`, 200 trials): `(0,1)` `syn +0.6337` per-pair `p_upper 0.000`; `(0,6)` `syn +0.1368` per-pair `p_upper 0.020`. Both were returned; the second is a family-wise false positive. The same multiplicity applied to `anti_interactions`, which returned 3 negative pairs on the same fixture.
- **Decision**: `scan_pairs(..., family_wise=True)` attaches a `family` block to every gate-passing pair. One target permutation per trial is scored against *every* valid pair; the trial's maximum and minimum gaps form the corrected null, and each observed gap gets `p_upper` against the max distribution and `p_lower` against the min distribution. `interactions` and `anti_interactions` select at `ALPHA=0.05` from those corrected tails. `family_wise=False` restores the per-pair tails and is the executable ablation. `pair_report(..., with_null=False)` skips the unused single-pair null inside a corrected scan. Tests: `tests/test_pair_scan_fwer.py` (8).
- **Consequences**: 846 tests OK; aikit check 5/5. On the planted trace the corrected scan keeps `(0,1)` at family `p_upper 0.005` and refuses `(0,6)` at `0.5522` with `family_size 28`; `anti_interactions` drops from 3 pairs to 0. On every shipped trace corrected `interactions` remains empty, so no shipped conclusion moves. Standing 89 steps / 11.0 reward and `policy_digest` decbfce3... are unchanged. Ablation: `family_wise=False` returns `[[0,1],[0,6]]` and 3 anti pairs; `family_wise=True` returns `[[0,1]]` and no anti pairs. Boundary: the correction is a max-statistic over the valid pairs of one scan; it does not make a trace with one variable in nine columns able to host an interaction, and the null is still a target permutation, so serial or autocorrelated alternatives are untested. It also does not gate target leakage: a column that is a deterministic function of the target can still enter a pair, which is the next falsifier.
